# MCP服务器架构重构说明

## 概述

本次重构将原始的单体 `mcp_server.py` 文件按照项目架构规范进行了拆分，实现了分层架构和关注点分离，提高了代码的可维护性和可扩展性。

## 重构架构

### 分层结构

```
services/api_service/
├── mcp/
│   └── mcp_server.py          # 主程序入口，负责启动和路由配置
├── controllers/
│   └── mcp_controller.py      # MCP控制器，处理HTTP请求和SSE连接
├── services/
│   ├── mcp_server_factory.py  # MCP服务器工厂，创建和配置服务器实例
│   └── mcp_tool_service.py    # MCP工具服务，处理工具执行业务逻辑
└── utils/
    ├── http_client.py         # HTTP请求构建器
    └── logging_config.py      # 日志配置工具
```

### 职责分离

#### 1. 主程序层 (`mcp_server.py`)
- **职责**: 应用启动和路由配置
- **功能**: 
  - 配置Starlette应用
  - 设置路由规则
  - 启动Uvicorn服务器

#### 2. 控制器层 (`mcp_controller.py`)
- **职责**: HTTP请求处理和SSE连接管理
- **功能**:
  - 处理SSE连接请求
  - 提取和验证请求参数
  - 管理MCP服务器生命周期
  - 统一错误处理

#### 3. 服务层 (`mcp_server_factory.py`, `mcp_tool_service.py`)
- **职责**: 业务逻辑处理
- **功能**:
  - MCP服务器实例创建和配置
  - 工具列表查询和工具调用处理
  - 数据库连接管理
  - 工具执行逻辑

#### 4. 工具层 (`http_client.py`, `logging_config.py`)
- **职责**: 基础设施和工具函数
- **功能**:
  - HTTP请求构建和参数处理
  - 统一日志配置管理
  - 工具函数和辅助类

## 重构优势

### 1. 可维护性提升
- **单一职责**: 每个模块只负责特定功能
- **低耦合**: 模块间依赖关系清晰，便于独立修改
- **高内聚**: 相关功能集中在同一模块内

### 2. 可扩展性改善
- **新功能添加**: 可以在相应层级添加新功能而不影响其他层
- **功能替换**: 可以独立替换某个组件（如HTTP客户端）
- **配置管理**: 统一的配置管理便于环境适配

### 3. 代码质量优化
- **错误处理**: 统一的错误处理机制
- **日志管理**: 结构化的日志输出和配置
- **类型安全**: 完整的类型注解提高代码安全性

### 4. 测试友好
- **单元测试**: 每个模块可以独立进行单元测试
- **Mock支持**: 依赖注入便于Mock测试
- **集成测试**: 分层结构便于不同层级的集成测试

## 使用示例

### 启动服务器
```python
from services.api_service.mcp.mcp_server import main

# 默认配置启动
main()

# 自定义端口启动
main(port=8802)
```

### 自定义日志配置
```python
from services.api_service.utils.logging_config import setup_logging

# 启用DEBUG级别日志
setup_logging(level="DEBUG")

# 同时输出到文件
setup_logging(level="INFO", log_file="mcp_server.log")
```
