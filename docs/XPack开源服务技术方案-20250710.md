# XPack开源服务技术方案-20250713

## 技术栈

- **MySQL 8.0+**: 关注数据一致性和事务完整性。
- **Python 3.9+**: 采用FastAPI框架开发API服务，结合SQLAlchemy进行数据库操作。
- **Redis**: 用于缓存MCP服务配置、用户会话和频繁访问的数据，降低数据库压力，提升响应速度。
- **RabbitMQ**: 消息队列，异步处理MCP服务调用计费信息，确保高吞吐量和可靠性。
- **OpenAPI Parser**: 利用`prance`或`pyyaml`解析OpenAPI/Swagger文档，自动化生成MCP服务配置。
- **Milvus** (可选): 支持MCP市场相似性搜索，当前开发优先级较低，暂以关键词搜索为主。

## 技术模块

### 用户身份验证

- **登录流程**:
  - 用户通过邮箱+密码或Google OAuth 2.0登录（管理后台服务提供端点）。
  - 验证成功后，生成30天有效期的JWT，存储于Redis。
  - 返回JWT给客户端，格式为`Bearer <token>`。
- **请求验证**:
  - 每次请求在`Authorization`头携带`Bearer <token>`。
  - 服务端（MCP服务、API服务、管理后台）验证token：
    - 检查token签名和过期时间。
    - 从Redis查询会话，确认用户状态（`is_active`）。
    - 返回用户ID和角色（`admin`或`user`），用于权限控制。
  - 无效或过期token返回401 Unauthorized错误。

### MCP服务

- **端口**: 默认监听8001端口。
- **功能**:
  - **用户鉴权**: 从Redis获取用户配置的MCP鉴权信息（如API密钥），整理后发送至API服务，验证请求头`Authorization: Bearer <token>`。
  - **动态注册**: 管理员上传OpenAPI/Swagger文档，解析后生成MCP服务配置，保存数据库并注册至Redis。
  - **服务上下架**: 根据Redis标志位控制服务状态。
- **稳定性设计**:
  - 使用`gunicorn`运行，支持多进程/多线程，结合`supervisor`管理进程，确保高可用。
  - 配置Redis缓存更新机制，避免频繁重启服务。
  - 日志记录调用信息，统一格式便于问题排查。

### 管理后台

- **端口**: 默认监听8002端口，独立运行，面向管理员和普通用户。
- **功能概述**:
  - **管理员功能**:
    - **数据统计仪表盘**: 展示用户总数、MCP服务调用次数、收入统计等核心指标。
    - **MCP服务管理**: 支持工具上下架、OpenAPI自动导入、服务配置编辑及Markdown格式说明文档设置。
    - **用户管理**: 查看用户列表、删除用户账户。
    - **收入管理**: 查看用户充值记录及收入汇总。
    - **支付渠道配置**: 配置Stripe API密钥、Webhook签名等。
    - **系统设置**: 管理全局配置，如平台LOGO，谷歌登录配置。
  - **普通用户功能**:
    - **MCP服务订阅**: 查看和订阅可用的MCP服务。
    - **调用统计**: 查询个人调用记录和费用明细。
- **登录与注册**:
  - **登录**: 验证邮箱+验证码或Google OAuth 2.0。
  - **注册**: 普通用户支持邮箱验证码注册（通过SMTP服务）和Google OAuth 2.0登录；管理员账户通过配置文件预设，禁止开放注册。
- **计费处理**:
  - 用户调用MCP服务且API返回200状态码时，生成调用消息，推送至RabbitMQ。
  - 异步消费者（运行于API服务）处理扣费，更新数据库和Redis缓存。
- **支付处理**:
  - **Stripe支付**: 创建支付会话，生成Checkout链接；Webhook接收支付结果，验证后更新用户余额。
  - **未来扩展**: 预留支付宝和微信支付接口。

### API服务

- **端口**: 默认监听8003端口，独立运行，处理MCP服务调用和鉴权。
- **功能**:
  - **用户鉴权**: 验证请求头`Authorization: Bearer <token>`，从Redis获取会话信息。
  - **工具转发**: 根据MCP工具配置，调用外部API，处理响应并记录日志。
  - **计费信息入队**: 将调用信息推送至RabbitMQ，支持按调用次数计费（优先），按Token计费（后续）。
- **异步任务**:
  - 运行RabbitMQ消费者，处理计费队列消息，执行余额扣减。

## 数据库设计

### 核心表结构

- **user**:
  - `id`: BIGINT, 主键，自增
  - `email`: VARCHAR(255), 唯一，邮箱地址
  - `password`: VARCHAR(255), 使用bcrypt加密存储
  - `role`: ENUM('admin', 'user'), 默认'user'
  - `balance`: DECIMAL(10,2), 用户余额
  - `created_at`: DATETIME, 创建时间
  - `is_active`: BOOLEAN, 账户状态，默认true
- **user_payment_order**:
  - `id`: BIGINT, 主键，自增
  - `user_id`: BIGINT, 外键，关联`user`表
  - `amount`: DECIMAL(10,2), 充值金额
  - `payment_method`: ENUM('stripe', 'alipay', 'wechat'), 支付方式
  - `status`: ENUM('pending', 'completed', 'failed'), 订单状态
  - `created_at`: DATETIME, 创建时间
  - `transaction_id`: VARCHAR(255), 支付平台交易ID
- **user_mcp_order**:
  - `id`: BIGINT, 主键，自增
  - `user_id`: BIGINT, 外键，关联`user`表
  - `mcp_tool_id`: BIGINT, 外键，关联`mcp_tool_api`表
  - `amount`: DECIMAL(10,2), 扣费金额
  - `call_count`: INT, 调用次数，默认1
  - `created_at`: DATETIME, 调用时间
- **mcp_tool_api**:
  - `id`: BIGINT, 主键，自增
  - `service_id`: BIGINT, 外键，关联`mcp_service`表
  - `url`: VARCHAR(255), API调用地址
  - `method`: ENUM('GET', 'POST', 'PUT', 'DELETE'), 请求方法
  - `params`: JSON, 请求参数
  - `body`: JSON, 请求体
  - `request_schema`: JSON, OpenAPI schema定义
  - `response_schema`: JSON, OpenAPI schema定义
  - `price`: DECIMAL(10,2), 每次调用单价
  - `billing_mode`: ENUM('per_call', 'per_token'), 计费模式
  - `is_active`: BOOLEAN, 是否上线
- **mcp_service**:
  - `id`: BIGINT, 主键，自增
  - `name`: VARCHAR(255), 服务名称
  - `description`: TEXT, 服务描述
  - `doc_md`: TEXT, Markdown格式说明文档
  - `category`: VARCHAR(50), 服务分类
  - `is_active`: BOOLEAN, 是否上线
  - `created_at`: DATETIME, 创建时间
- **sys_config**:
  - `id`: BIGINT, 主键，自增
  - `key`: VARCHAR(100), 配置键（如`stripe_api_key`）
  - `value`: TEXT, 配置值
  - `description`: TEXT, 配置描述

## 配置信息

- **Redis**:
  - 所有缓存键使用`xpack:`前缀。
  - 通过环境变量配置主机、端口、密码。
  - 缓存键设计：
    - `xpack:user:session:{token}`: 用户会话信息（存储JWT和用户状态）。
    - `xpack:mcp:service:{service_id}`: MCP服务配置。
    - `xpack:user:balance:{user_id}`: 用户余额缓存。
- **RabbitMQ**:
  - 配置交换机和队列：
    - Exchange: `xpack_mcp_billing`, 类型direct。
    - Queue: `xpack_mcp_billing_queue`, 绑定routing key `billing`.
  - 启用消息持久化，确保计费消息可靠传递。
- **MySQL**:
  - 使用SQLAlchemy管理数据库连接池，支持高并发访问。
  - 通过环境变量配置主机、端口、用户名、密码。
- **Stripe**:
  - 配置API密钥和Webhook签名，存储于`sys_config`表。
  - Webhook通知端点。

## 部署架构

- **服务部署**:
  - **MCP服务**: 使用`gunicorn`运行于端口8001，配置多进程/多线程，`supervisor`管理进程。
  - **管理后台**: 使用`uvicorn`运行于端口8002，支持高并发用户请求。
  - **API服务**: 使用`uvicorn`运行于端口8003，处理MCP调用和计费任务。
- **容器化**: 使用Docker Compose编排三个服务，`common`模块随服务复制到容器。
- **日志系统**: 按服务分目录存储日志（`logs/mcp_service/`、`logs/admin_service/`、`logs/api_service/`）。
